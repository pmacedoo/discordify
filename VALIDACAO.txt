Discordify 1.1.0 — Windows x64 validation

Actual FFmpeg conversions on the test PC (NVIDIA GeForce RTX 5060):
  Source: 26,235,958 bytes, 720p, 60 FPS, 480 frames, with audio.
  CPU one-pass:   16,770,981 bytes; full decode and 480 frames confirmed.
  NVENC one-pass: 16,927,370 bytes; full decode and 480 frames confirmed.
  Auto calibration selected NVENC for this profile and CPU for smaller clips.
  Full conversion plus validation: CPU 3.233s; NVENC 2.292s on this sample.
  These sample timings are not a universal speedup claim.

Actual additional tests:
  29.97 FPS: 90 frames preserved on CPU and NVENC.
  Variable FPS: 120 frames preserved on CPU and NVENC.
  Frame timestamps compared within 1.1 ms between containers.
  Existing small MP4 retained without recoding.
  Active FFmpeg cancellation and invalid input handling passed.
  Cached encoder choice reused without repeating benchmark calls.
  Six selection/cache policy unit tests passed.

Fallback error-path test:
  GPU device loss was simulated through the explicit process-runner boundary.
  A partial temporary output was replaced by a real CPU FFmpeg conversion.
  Completed output preserved all 480 frames; original bytes stayed unchanged.
  This validates fallback control flow, not physical unplugging of a GPU.

Hardware coverage:
  NVIDIA NVENC and CPU were exercised on actual hardware.
  Intel QSV and AMD AMF are supported adapters but were not validated on
  physical Intel/AMD GPU hardware in this environment.

Interface:

  Qt equivalent drag/drop events were used for UI flow verification.
  Physical Explorer drag/drop was not automated.

Cache:
